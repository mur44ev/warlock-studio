# Прошивка и восстановление

## Поддерживаемое устройство

GP75 v1.04 model919, преобразованная Warlock с YC3121-L. Проводной USB3151:4015,
FFFF:2; radio receiver3151:4011; boot3151:4016 FF01:1. Флешер не выполняет
первоначальную конвертацию model1126 и не предназначен для похожих моделей.
Заливка — только по кабелю. Не отключайте питание до verify55 и возврата приложения.

В архиве firmware сохранена структура `firmware/aw60`. В корне лежит `hidapi.dll`.
Host-скрипты используют Python3 x64 и стандартную библиотеку; OpenRGB не требуется.
Можно задать путь к другой совместимой DLL через `WARLOCK_HIDAPI`.

```powershell
# По умолчанию только инвентаризация/backup и проверка образа.
py -3 firmware/aw60/flash_aw60.py
# Запись проверенного rev9; backup пресетов должен пройти до boot entry.
py -3 firmware/aw60/flash_aw60.py --flash
```

Рядом со скриптами сохраняются JSON-логи и копии пресетов. Они содержат локальные
USB-пути/настройки: не публикуйте их без проверки. Сохранение пресетов не является
снятием полного дампа flash или гарантией восстановления всех пользовательских настроек.

## Проверка после записи

Закройте Studio. Используйте свою исправную pre-flash копию `custom-....json`:

```powershell
py -3 firmware/aw60/verify_device.py --baseline firmware/aw60/custom-....json --soak 20
# После переключения в 2.4 GHz:
py -3 firmware/aw60/verify_device.py --radio --baseline firmware/aw60/custom-....json --soak 20
```

Во время проверки idle matrix не нажимайте клавиши. Затем вручную проверьте
набор, Enter, Fn, энкодер и эффекты. Нельзя считать исправный idle matrix проверкой
всех физических клавиш. Логи/счётчики кадров не доказывают оптическую частоту PWM.

## Исправление уже повреждённой раскладки после rev8

Сначала установите rev9: rev7/rev8 снова портят общий буфер. Затем выберите
**свою** заведомо исправную копию обоих слоёв и правильного аппаратного профиля:

```powershell
py -3 firmware/aw60/repair_layout.py --baseline firmware/aw60/GOOD-custom.json
py -3 firmware/aw60/repair_layout.py --baseline firmware/aw60/GOOD-custom.json --apply --force
```

Первый вызов не пишет. Второй сохраняет текущее состояние до записи, восстанавливает
504 значимых байта каждого слоя и проверяет чтением. Последние8 байт принадлежат стоку.
Предпрошивочный backup повреждённого rev8 уже может быть испорчен; сравнивать только
с последним логом недостаточно. Чужих раскладок и персональных backup в релизе нет.

## Откат на сток

Положите собственный исходный `919_v104.bin` в `firmware/stock/`; проверяется хеш,
указанный в [firmware/stock/README.md](../firmware/stock/README.md).

```powershell
py -3 firmware/aw60/flash_aw60.py --rollback --flash
```

Если приложение не отвечает, но **известный boot3151:4016 уже появился по USB**:

```powershell
py -3 firmware/aw60/recover_boot.py
py -3 firmware/aw60/recover_boot.py --flash
```

Эта утилита пишет только hash-checked stock. Принудительный аппаратный вход в boot
при мёртвом приложении не проверен; гарантированного unbrick здесь нет. Никакого
SWD unlock, изменения pairing или прошивки receiver эти инструменты не выполняют.
